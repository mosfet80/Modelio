  <files>
    ../platform.search.engine.test/src/org/modelio/platform/query/engine/acceptance/AcceptanceFixture.java
  </files>
  <action>
    Create `AcceptanceFixture.java` in the `engine/acceptance/` sub-package.

    The fixture builds one **rich in-memory model** that covers all Q1–Q15 requirements. It extends
    no base class — it is a helper that receives a `TestModelFactory` and populates it.

    **Model structure** (minimum):

    ```
    Packages:
      - rootPkg (Package)
        ├── domainPkg (Package)
        │   ├── Customer (Class)
        │   ├── Order (Class)
        │   └── Account (Class)
        └── utilPkg (Package)
            └── Helper (Class)

    Inheritance (Generalization links):
      - Customer extends AbstractThing (Class) — Generalization forward
      - SpecialCustomer (Class) extends Customer — Generalization forward
      - VipCustomer (Class) extends SpecialCustomer — Generalization forward

    Dependencies (Dependency links):
      - Customer -> Order (Dependency forward)
      - Order -> Account (Dependency forward)
      - Helper -> Customer (Dependency forward)

    Interfaces + mixed model elements:
      - Printable (Interface) — for kind filtering tests
      - AuditLog (Class) — for "no extra results" verification

    Cycle setup (for Q8):
      - CycleA (Class), CycleB (Class), CycleC (Class)
      - CycleA -> CycleB (Generalization), CycleB -> CycleC (Generalization), CycleC -> CycleA (Generalization)
    ```

    The fixture class has:
    - A `populate(TestModelFactory)` static method that creates all elements.
    - Public fields or a record holding references to all created elements by name for assertion use.
    - A `QueryEngine createEngine(ICoreSession, Supplier)` helper.

    **Key design decisions:**
    - setOwner for all elements so they are reachable in composition tree.
    - All elements named distinctly — no name collisions across metaclasses.
    - Package ownership via Owner/OwnedElement dependency.
  </action>
