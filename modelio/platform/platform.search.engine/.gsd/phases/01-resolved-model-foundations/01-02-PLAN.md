  <action>
    Implement internal resolved reference types aligned with Phase 1 context:

    - Kind alternatives:
      - Metaclass kind backed by `MClass`
      - Stereotype kind backed by `Stereotype`

    - Edge alternatives:
      - Dependency edge backed by `MDependency`
      - Link-object edge backed by link metaclass `MClass` (and optionally stereotype)
      - Direction metadata (forward/backward/both) should be part of the type model

    - Property-key alternatives:
      - Attribute backed by `MAttribute`
      - Tag backed by `TagType`
      - Note backed by `NoteType`
      - Property definition backed by `PropertyDefinition`

    Each ref should model ambiguity as `Alternatives<...>`.

    Keep these types in the internal `...engine.resolved` package so Phase 2 resolver and Phase 4 executor can share them.
