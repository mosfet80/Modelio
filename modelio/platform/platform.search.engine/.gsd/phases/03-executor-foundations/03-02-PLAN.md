**A. Create `SourceEvaluator`** in `internal/executor/SourceEvaluator.java`:

A utility class (or sealed strategy) that evaluates a `ResolvedSource` into a stream of `MObject` elements, pushing them into a `StreamingQueryResponse.ExecutionContext` (or equivalent callback). The evaluator also pushes diagnostics for edge cases.

API pattern (static methods or a simple class):
```java
class SourceEvaluator {
    /**
     * Evaluate the source, pushing items and diagnostics into the execution context.
     * Called from within the background producer thread of StreamingQueryResponse.
     */
    static void evaluate(ResolvedSource source, ICoreSession session, ExecutionContext ctx) { ... }
}
```

Where `ExecutionContext` is the interface provided by `StreamingQueryResponse` (from Plan 03-01) giving access to `pushItem()`, `pushDiagnostic()`, `isDisposed()`.

**ProvidedSource evaluation:**
- Iterate over `source.elements()`.
- For each element:
  - Check `isDisposed()` → if true, stop immediately (best-effort stop).
  - Check `element.isValid()` and `!element.isDeleted()` → if invalid/deleted, do NOT push as item. Instead, collect into a list for aggregated diagnostic.
  - If valid: push as `NodeWithExplainOut(element, trivialPath)` where `trivialPath = new PathOutput(List.of(element), List.of())` (single source node, no traversal steps).
- After iteration, if any invalid/deleted elements were skipped:
  - Push ONE aggregated warning diagnostic: `Diagnostics.warning(DiagnosticCode.INVALID_ELEMENT_SKIPPED, "Skipped N invalid/deleted element(s)", skippedElements)` (capped at 500 by the Diagnostics factory).
- If the provided `Iterable` was empty (zero valid elements, zero skipped):
  - Push an info diagnostic: `Diagnostics.info(DiagnosticCode.EMPTY_PROVIDED_SOURCE, "Provided source is empty: no elements to process")`.
- **Null provider return (checked at QueryEngine level, not here).**

**AllSource evaluation:**
- Read `source.kind()` which is a `ResolvedKind` with a list of `KindAlternative`.
- If kind is unknown (`kind.isUnknown()`): Push warning diagnostic and stop (no items).
- For each `KindAlternative`:
  - Check `isDisposed()` before processing each alternative.
  - If `MetaclassKind(MClass metaclass)`:
    - Call `session.getModel().findByClass(metaclass, true)` → returns `Collection<? extends MObject>`.
    - Iterate the collection. For each element: check validity, push valid ones as `NodeWithExplainOut(element, trivialPath)`, collect invalid ones.
  - If `StereotypeKind(Stereotype stereotype)`:
    - Call `stereotype.getExtendedElement()` → returns `List<ModelElement>`.
    - Iterate. Same validity check + push pattern.
- After all alternatives processed: push aggregated invalid-element diagnostic if any.
- **No deduplication across alternatives for now** — Phase 4 handles dedup for unions. For Phase 3, if the same element appears via multiple alternatives, it appears multiple times in the output. This is acceptable.

**Ordering**: Session-natural order (no sort). Process alternatives in list order.

Use `Log.trace()` for internal tracing: "Evaluating ProvidedSource with N elements", "Evaluating AllSource with N alternatives", "Alternative MetaclassKind(X) produced N items".

**A. Implement `QueryEngine.execute()`** — replace the current stub:

The current implementation in `QueryEngine.execute()`:
```java
ResolutionResult resolvedQuery = this.resolver.resolveQuery(query);
throw new UnsupportedOperationException("Not implemented yet");
```

Replace with:

```java
public IQueryResponse execute(Query query) {
    // 1. Resolve the query
    ResolutionResult resolution = this.resolver.resolveQuery(query);
    List<Diagnostic> resolutionDiagnostics = resolution.diagnostics();

    // 2. Check for resolution errors — refuse execution if any error-level diagnostic
    boolean hasResolutionErrors = resolutionDiagnostics.stream()
        .anyMatch(d -> d.level() == Diagnostic.Level.ERROR);

    if (hasResolutionErrors) {
        // Return empty response with resolution diagnostics + execution refusal diagnostic
        List<Diagnostic> allDiags = new ArrayList<>(resolutionDiagnostics);
        allDiags.add(Diagnostics.error(DiagnosticCode.RESOLUTION_ERROR,
            "Execution refused: resolution produced error-level diagnostics"));
        return StreamingQueryResponse.empty(allDiags);
    }

    ResolvedQuery resolved = resolution.resolvedQuery();

    // 3. For Phase 3: assert no steps (future phases will add step processing)
    //    If steps are present, return an error response (not yet implemented)
    if (!resolved.steps().isEmpty()) {
        List<Diagnostic> allDiags = new ArrayList<>(resolutionDiagnostics);
        allDiags.add(Diagnostics.error(DiagnosticCode.UNSUPPORTED_STEP,
            "Step execution is not yet implemented"));
        return StreamingQueryResponse.empty(allDiags);
    }

    // 4. Create streaming response with source evaluation as the execution task
    ICoreSession sessionRef = this.session;
    Supplier<Iterable<MObject>> providerRef = this.selectionProvider;

    return StreamingQueryResponse.create(resolutionDiagnostics, ctx -> {
        // Resolve ProvidedSource's selectionProvider if needed
        ResolvedSource source = resolved.source();
        if (source instanceof ResolvedSource.ProvidedSource provided) {
            // The resolved ProvidedSource already has elements from resolution
            SourceEvaluator.evaluate(source, sessionRef, ctx);
        } else if (source instanceof ResolvedSource.AllSource) {
            SourceEvaluator.evaluate(source, sessionRef, ctx);
        }
    });
}
```

**Important details:**
- The `ProvidedSource` in the resolved model already contains the `Iterable<MObject>` from resolution. However, per the CONTEXT decision, if the query has a `ProvidedSource`, the resolver should wire in the elements from the `selectionProvider`. Check the current `QueryResolver` to see how `ProvidedSource` is resolved. If the resolver already calls the selectionProvider during resolution, then `SourceEvaluator` just iterates the resolved elements. If NOT, then `QueryEngine.execute()` needs to fetch from `selectionProvider` and pass to the evaluator.

- **Null selectionProvider check**: If the query source is `ProvidedSource` and the selectionProvider's `get()` returns `null`, throw `NullPointerException("selectionProvider returned null — this is a programming error")`. This check should happen before creating the StreamingQueryResponse (since it's a programming error, it should propagate as an exception, not be caught by the response's error handler). Check the resolver to see where selectionProvider is called — it might already be handled there.

- Log: `Log.trace("Executing query: source=%s, steps=%d", resolved.source().getClass().getSimpleName(), resolved.steps().size())`.
