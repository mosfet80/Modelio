**A. Create `BufferedAsyncIterator<T>`** in `internal/executor/BufferedAsyncIterator.java`:

Implements `AsyncIterator<T>`. Thread-safe, backed by a `LinkedBlockingQueue<T>` (or equivalent).

API:
- `push(T item)`: Adds item to the queue. Called by producer thread. If disposed, silently drops.
- `complete()`: Signals no more items will be pushed. After this, `hasNext()` returns false once queue is drained.
- `dispose()`: Sets a volatile `disposed` flag. Puts a poison pill in the queue to unblock any waiting consumer. After dispose, `next()` returns null, `hasNext()` returns false, any pending `CompletableFuture` from `onNext()` completes with null.

AsyncIterator contract:
- `next()`: Polls queue (non-blocking). Returns null if empty or disposed.
- `hasNext()`: Returns true if queue is non-empty OR producer hasn't called `complete()` yet (more items could arrive). Returns false if disposed or (queue is empty AND complete).
- `onNext()`: Returns a `CompletableFuture<T>` that completes when the next item arrives. If already has an item queued, completes immediately. If complete/disposed, completes with null. Use a single pending future field (only one outstanding onNext at a time). Use `take()` in a dedicated drainer or use queue polling with a condition.

Threading considerations:
- Producer thread calls `push()` and `complete()`.
- Consumer thread calls `next()`, `hasNext()`, `onNext()`.
- `dispose()` can be called from any thread.
- Use `volatile` for the `disposed` and `completed` flags.
- The blocking queue provides the thread-safe handoff.

For `onNext()` implementation: Spawn a short-lived virtual thread (or use a small executor) that calls `take()` on the queue and completes the future. Alternatively, use `CompletableFuture.supplyAsync()`. Keep it simple — avoid complex lock choreography.

**B. Create `EmptyAsyncIterator<T>`** in `internal/executor/EmptyAsyncIterator.java`:

**C. Create `StreamingQueryResponse`** in `internal/executor/StreamingQueryResponse.java`:

Implements `IQueryResponse`. Core class of the execution infrastructure.

Fields:
- `BufferedAsyncIterator<NodeWithExplainOut> itemsBuffer` — items stream
- `BufferedAsyncIterator<Diagnostic> diagnosticsBuffer` — diagnostics stream
- `volatile boolean truncated` — initially false, set to true if execution stopped early
- `volatile boolean disposed` — tracks dispose state
- `Thread producerThread` — the background execution thread (or null if not started)

Construction pattern — use a **static factory or builder** (not public constructor):
- `StreamingQueryResponse.create(List<Diagnostic> resolutionDiagnostics, Runnable executionTask)`: 
  - Creates items and diagnostics buffers.
  - Pre-loads diagnostics buffer with all resolution diagnostics (immediately available).
  - Starts a daemon background thread that runs `executionTask`. The task receives a `StreamingQueryResponse.ExecutionContext` providing `pushItem(NodeWithExplainOut)`, `pushDiagnostic(Diagnostic)`, `isDisposed()`, `setTruncated()`.
  - When the task completes (normally or exceptionally): calls `itemsBuffer.complete()`, pushes any final diagnostics (interrupted diagnostic if disposed), then calls `diagnosticsBuffer.complete()`.

IQueryResponse implementation:
- `items()`: Returns `this.itemsBuffer` (always the same instance).
- `diagnostics()`: Returns `this.diagnosticsBuffer` (always the same instance).
- `isTruncated()`: Returns `this.truncated`.
- `dispose()`: Sets `disposed` flag. Disposes both buffers. If the producer thread is still running, interrupts it. Per CONTEXT: the current item in production may finish, but no new items are emitted after. Any pending `CompletableFuture` completes with null. A `Diagnostic(DiagnosticCode.INTERRUPTED, Level.INFO, "Query execution was interrupted", List.of())` is pushed to diagnostics before completing the diagnostics buffer.

Error handling in the execution task wrapper:
- If the `executionTask` throws an exception that is NOT an `InterruptedException`:
  - Push an error diagnostic: `Diagnostic(DiagnosticCode.RUNTIME_ERROR, Level.ERROR, "Execution error: " + e.getMessage(), List.of())`.
  - Set `truncated = true` (partial results preserved).
  - Complete both buffers gracefully.
- If `InterruptedException` (from dispose): Push interrupted diagnostic, complete buffers.
- Programming bugs (Error subclasses like `OutOfMemoryError`): Let them propagate — do NOT catch.

Use `Log.trace()` for internal tracing (e.g., "Starting execution thread", "Execution complete, N items produced").

Also provide a static factory for error/empty responses:
- `StreamingQueryResponse.empty(List<Diagnostic> diagnostics)`: Returns a response with no items, not truncated, diagnostics pre-loaded. Used when resolution errors prevent execution.
