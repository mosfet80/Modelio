# Phase 3.03: Refactor Again Response API - Context

**Gathered:** 2026-02-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Refactor query execution APIs to fully separate synchronous and asynchronous execution contracts. This phase defines API shape, lifecycle, callback contract, and migration behavior only; it does not add new query semantics or capabilities.

</domain>

<decisions>
## Implementation Decisions

### Sync execution contract

- Keep a dedicated synchronous entry point: `syncExec(Query)`.
- `syncExec(Query)` is blocking and returns only when query execution is finished, either normally or with error.
- Error contract is hybrid:
  - query/runtime issues are represented in response diagnostics/state,
  - unrecoverable framework-level failures may still throw.
- Keep sync API pure blocking in this phase (no timeout/cancellation parameter on `syncExec`).
- Item/diagnostic ordering does not need strict deterministic stability when multiple equivalent orders exist.

### Async execution lifecycle and naming

- Replace immediate async-start shape with a prepared execution handle returned by engine.
- Keep method split as: `syncExec(Query)` + `prepareAsync(Query)`.
- Rename async handle away from response naming; preferred name: `IASyncExecution`.
- `prepareAsync(Query)` returns a not-started execution handle.
- Handlers must be registered before start.
- Execution starts explicitly via `run()`, which returns `CompletableFuture<QueryResponseState>`.
- `run()` is single-use; subsequent calls are rejected (fail fast).

### Async callback contract

- Async callback model includes:
  - `onItem(Consumer<NodeWithExplainOut>)`
  - `onDiagnostic(Consumer<Diagnostic>)`
  - `onComplete(Consumer<QueryResponseState>)`
  - `state()`
- Each `onXxx(...)` registration method returns the same execution handle to support fluent chaining.
- Producer-thread callback invocation is acceptable by default.
- Ordering guarantees are per-stream only:
  - item callbacks preserve item emission order,
  - diagnostic callbacks preserve diagnostic emission order,
  - no global cross-stream total ordering required.
- Support multiple handlers per stream.
- Completion handlers must also be registered before starting execution (no late registration semantics in scope). Any handler registration after start is considered misuse and should fail fast.

### State and cancellation

- Sync and async should share the same lifecycle enum: `QueryResponseState`.
- Add explicit async cancellation API in this phase: `cancel()` on async execution handle.

### Migration policy

- Existing `IQueryEngine.execute(Query)` should be removed immediately (intentional breaking change).
- No compatibility bridge/deprecation period required for this phase.

### Copilot's Discretion

- Final spelling/casing normalization for async handle name if needed (while preserving the decided concept and semantics).
- Exact exception types for fail-fast invalid lifecycle calls.
- Exact thread-safety mechanics for handler registration, state transitions, and callback emission.

</decisions>

<specifics>
## Specific Ideas

- Separate API intent clearly: sync path returns finalized response; async path is configured then started.
- Fluent registration style is preferred for async handler wiring.

</specifics>
