  <action>
Create four new classes under `org.modelio.platform.query.internal.executor`:

**1. `KindMatcher.java`** — Final utility class (no instances).
- Public static method `boolean matches(MObject element, ResolvedKind kind)`.
- If `kind.isUnknown()` → return false.
- Iterate all `KindAlternative` alternatives with OR semantics:
  - `MetaclassKind mk` → `element.getMClass().hasBase(mk.metaclass())` returns true → match.
  - `StereotypeKind sk` → cast element to `ModelElement`, call `me.getExtension().contains(sk.stereotype())`. If element is not a `ModelElement`, this alternative doesn't match.
  WARNING: match must be exact for concrete metaclass/stereotype (no inheritance) , with inheritance if the alternative metaclass/stereotype is abstract. This is consistent with MQL semantics and user expectations.
- Return false if no alternative matches.

**2. `PropertyValueReader.java`** — Final utility class.
- Public static method `Object readValue(MObject element, ResolvedProperty property)`.
- If `property.isUnknown()` → return null.
- Iterate alternatives with OR semantics: try each `PropertyAlternative` in order and return the first non-null result:
  - `ResolvedMAttribute a` → `element.mGet(a.attribute())`.
  - `ResolvedTagType t` → if `element instanceof ModelElement me`, call `me.getTagValue(t.tagType())`. Returns String or null.
  - `ResolvedNoteType n` → if `element instanceof ModelElement me`, call `me.getNoteContent(n.noteType())`. Returns String or null.
  - `ResolvedPropertyDefinition pd` → if `element instanceof ModelElement me`, switch on `pd.owner()`:
    - `OwnerStereotype os` → `me.getProperty(os.stereotype(), pd.propertyDefinition().getName())`
    - `OwnerReference or` → `me.getProperty(or.reference(), pd.propertyDefinition().getName())`
  - If element is not a `ModelElement` for tag/note/propdef alternatives, that alternative returns null (skip to next).
- Return null if no alternative produces a non-null value. **Never throw** — property absence returns null, which callers interpret as "element excluded".

**3. `ExpressionEvaluator.java`** — Final utility class.
- Public static method `boolean evaluate(ResolvedExpr expr, MObject element, ICoreSession session)`.
- Use switch pattern matching on the sealed `ResolvedExpr` hierarchy:
  - `ResolvedAndExpr and` → all operands (from `and.exprs()`) must evaluate to true. Empty list → true.
  - `ResolvedOrExpr or` → any operand (from `or.exprs()`) must evaluate to true. Empty list → false.
  - `ResolvedNotExpr not` → negate `evaluate(not.expr(), element, session)`.
  - `ResolvedIsExpr is` → delegate to `KindMatcher.matches(element, is.kind())`.
  - `ResolvedCompareExpr cmp` → call private `evaluateCompare(cmp, element, session)`:
    - Read left value: call private `resolveValue(cmp.left(), element)`.
    - Read right value: call private `resolveValue(cmp.right(), element)`.
    - `resolveValue` for `ResolvedPropertyValueExpr` → `PropertyValueReader.readValue(element, pvExpr.key())`.
    - `resolveValue` for `LiteralValueExpr` → return its `value()` directly.
    - `resolveValue` for `UnsupportedValueExpr` → return null.
    - If either operand is null → return false (per CONTEXT.md: null comparisons are permissive, absence/empty treated equivalently).
    - Apply comparison operator `cmp.op()`:
      - `"="` / `"eq"` → `String.valueOf(left).equalsIgnoreCase(String.valueOf(right))`.
      - `"!="` / `"neq"` → negation of `=`.
      - `"<"` / `"lt"`, `">"` / `"gt"`, `"<="` / `"lte"`, `">="` / `"gte"` → attempt numeric comparison first (`Double.parseDouble`), fall back to lexicographic `String.valueOf(left).compareTo(String.valueOf(right))`. Catch `NumberFormatException` → fall back to lexicographic.
      - `"contains"` → `String.valueOf(left).toLowerCase().contains(String.valueOf(right).toLowerCase())`.
      - `"startsWith"` / `"starts_with"` → `String.valueOf(left).toLowerCase().startsWith(String.valueOf(right).toLowerCase())`.
      - Unknown operator → return false.
  - `ResolvedExistsExpr ex` → call private `evaluateExists(ex, element, session)`:
    - Create a singleton list `List.of(new NodeWithExplainOut(element, new PathOutput(List.of(element), List.of())))`.
    - Apply `StepPipelineExecutor.executeSteps(ex.in(), singletonList, session)` to get sub-results.
    - If `ex.where()` is not null, filter sub-results with `evaluate(ex.where(), subResult.node(), session)`.
    - Return true if any sub-results remain.
  - `ResolvedExpr.UnsupportedExpr` → return false (defensive: exclude).

**4. `StepPipelineExecutor.java`** — Final utility class.
- Public static method `void execute(List<ResolvedStep> steps, List<NodeWithExplainOut> sourceItems, ICoreSession session, IQueryResponseFiller filler)`:
  - Call `executeSteps()` to run the pipeline, then dedup and push results.
  - Dedup: iterate results with a `LinkedHashSet<String>` keyed by `item.node().getUuid()`. For each item, if UUID is new, call `filler.pushItem(item)` (checking `filler.isComplete()` before each push).
- Package-private static method `List<NodeWithExplainOut> executeSteps(List<ResolvedStep> steps, List<NodeWithExplainOut> input, ICoreSession session)`:
  - Iterate steps sequentially, transforming the current list through each step.
  - Use switch on `ResolvedStep`:
    - `FilterStep f` → call private `executeFilter(f, input, session)`.
    - `TraverseStep t` → return empty list with WARN log (to be implemented in 04-02).
    - `UnionStep u` → return empty list with WARN log (to be implemented in 04-03).
    - `RepeatStep r` → return empty list + log info (out of scope, Phase 5).
    - `UnsupportedStep us` → return empty list + log warning.
- Private `executeFilter(FilterStep step, List<NodeWithExplainOut> input, ICoreSession session)`:
  - For each item in input, evaluate `ExpressionEvaluator.evaluate(step.predicate(), item.node(), session)`.
  - Keep items where predicate is true. Pass through the same `NodeWithExplainOut` (path unchanged by filter).
  - Return filtered list.

All classes: package `org.modelio.platform.query.internal.executor`. Use `this.` for instance fields. Use explicit types (no `var`). Add Javadoc to public methods. Use `SearchEngine.LOG` for debug/warning logging. Import `PluginLogger` from `org.modelio.platform.utils.log.writers`.

**1. Modify `QueryEngine.runQuery()`** to remove the UNSUPPORTED_STEP gate and wire the step pipeline:

Replace the block:
```java
if (!resolvedQuery.steps().isEmpty()) {
    responseFiller.pushDiagnostic(Diagnostics.error(
            DiagnosticCode.UNSUPPORTED_STEP,
            "Step execution is not yet implemented"));
    responseFiller.getState().complete(QueryCompletionStatus.FAILED);
    return;
}

SourceEvaluator.evaluate(resolvedQuery.source(), this.session, responseFiller);

responseFiller.getState().complete(QueryCompletionStatus.ENDED);
```

With:
```java
if (resolvedQuery.steps().isEmpty()) {
    // No steps: direct push to response (existing fast path)
    SourceEvaluator.evaluate(resolvedQuery.source(), this.session, responseFiller);
} else {
    // Collect source items, then run through step pipeline
    SyncQueryResponse sourceCollector = new SyncQueryResponse();
    SourceEvaluator.evaluate(resolvedQuery.source(), this.session, sourceCollector);

    // Transfer source diagnostics to real response
    sourceCollector.diagnostics().forEach(responseFiller::pushDiagnostic);

    // Execute step pipeline with dedup
    StepPipelineExecutor.execute(
            resolvedQuery.steps(),
            sourceCollector.items(),
            this.session,
            responseFiller);
}

responseFiller.getState().complete(QueryCompletionStatus.ENDED);
```
