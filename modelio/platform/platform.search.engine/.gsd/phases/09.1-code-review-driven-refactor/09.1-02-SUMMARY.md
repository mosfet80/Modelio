# Phase 09.1 Plan 02: SyncQueryResponse Merge Logic + Contract Javadoc Summary

SyncQueryResponse now groups multiple (node, path) emissions into merged NodeWithExplainOut entries; streaming contract documented on IASyncExecution and PreparedAsyncExecution.

## What Was Built

### Task 1: SyncQueryResponse — merge-by-node via LinkedHashMap

Replaced the flat `List<NodeWithExplainOut> items` field with a `LinkedHashMap<MObject, NodeWithExplainOut> itemsByNode`.

- `pushItem()` calls `itemsByNode.merge(item.node(), item, ...)` — on collision, merges path sets via `LinkedHashSet`
- `items()` returns `List.copyOf(itemsByNode.values())` — deduplicated, one entry per unique node
- Constructor simplified: no more `new ArrayList<>()` for items
- Added imports: `LinkedHashMap`, `LinkedHashSet`, `Set`, `PathOutput`, `MObject`

### Task 2: Javadoc — streaming contract documentation

- `IASyncExecution.onItem()`: new Javadoc documents that the same node may be reported multiple times (once per path), and that consumers needing grouped results must accumulate by node identity
- `PreparedAsyncExecution`: new class-level Javadoc describes the per-(node,path) emission semantics and that diagnostic/completion handlers fire at most once
- `complete()` comment updated: "Streaming — items pushed immediately, nothing to flush."
