# Phase 09.1 Plan 01: Remove Batching, Add Streaming Terminal Consumer Summary

Removed batching infrastructure from `StepPipelineExecutor.buildPipeline()` and replaced it with a pure-streaming terminal that emits one `NodeWithExplainOut` per `(node, path)` pair immediately as items arrive.

## What Was Done

### Task 1: Rewrite terminal consumer

- Deleted `currentBatch` (`LinkedHashMap<String, NodeAccumulator>`) — the per-source-item batch
- Deleted `globalEmitted` (`Set<MObject>`) — the polluted cross-batch dedup set
- Added `emittedNodeUuids` (`Set<String>`) — UUID-based dedup where only first path per node counts against budget
- Terminal consumer now emits `downstream.pushItem(new NodeWithExplainOut(item.node(), List.of(item.path())))` immediately per `TraversalItem`
- `pushItem()` now iterates `item.whyPaths()` with a `for` loop — all source paths are fed into `chainHead` (no silent drop of non-first paths)
- `complete()` body is empty (no flush needed — pure streaming)
- Removed unused imports: `LinkedHashMap`, `LinkedHashSet`, `Collection`

### Task 2: Delete NodeAccumulator inner class

- Deleted the entire `NodeAccumulator` private static inner class (no longer referenced)
- Updated class-level Javadoc: removed "per-source-item batch" / "batch flush" language; states the pipeline is a pure stream of `(node, path)` pairs; notes that dedup/grouping is the response layer's responsibility
- Updated `buildPipeline()` Javadoc: removed stale `pushTraversalItem` reference; documents UUID-based budget enforcement and immediate-emit semantics
