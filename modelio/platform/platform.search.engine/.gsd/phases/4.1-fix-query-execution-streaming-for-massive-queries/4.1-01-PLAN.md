<objective>
Refactor the step execution pipeline from list-passing to a push-based consumer chain, eliminating intermediate `List<NodeWithExplainOut>` buffering between steps.

Purpose: Current execution materializes all source elements into a `SyncQueryResponse` before running steps, and each step creates a new `ArrayList` for its output. For model-wide queries producing tens of thousands of elements, this causes memory pressure and defeats streaming semantics. The push model makes each step a `Consumer<NodeWithExplainOut>` wrapper that processes and forwards items one-by-one.

Output: Rewritten `StepPipelineExecutor` with `buildPipeline()` entry point, simplified `QueryEngine.runQuery()` wiring, adapted `ExpressionEvaluator.evaluateExists()`, and all existing tests passing unchanged.
</objective>

  <action>
  Rewrite `StepPipelineExecutor` from list-passing architecture to push-based consumer chain. The core idea: each step wraps a `Consumer<NodeWithExplainOut>` downstream, forming a chain from first step to terminal dedup consumer. Source items enter the chain head and flow through each step without intermediate list accumulation.

  **StepPipelineExecutor changes (complete rewrite of public/package-private API):**

  1. **Replace `execute(List<ResolvedStep>, List<NodeWithExplainOut>, ICoreSession, IQueryResponseFiller)`** with a new public method:
     ```java
     public static IQueryResponseFiller buildPipeline(
             List<ResolvedStep> steps, ICoreSession session, IQueryResponseFiller downstream)
     ```
     This method:
     - Creates a terminal `Consumer<NodeWithExplainOut>` that deduplicates by UUID (`LinkedHashSet<String>`) and calls `downstream.pushItem()` for new items. Check `downstream.isComplete()` before pushing.
     - Calls `buildChain(steps, terminal, session)` to get the chain head consumer.
     - Returns an `IQueryResponseFiller` implementation (anonymous inner class) that:
       - `pushItem(item)` → delegates to the chain head consumer's `accept(item)`
       - `pushDiagnostic(d)` → delegates to `downstream.pushDiagnostic(d)`
       - `setTruncated()` → delegates to `downstream.setTruncated()`
       - `getState()` → delegates to `downstream.getState()`

  2. **Add private `buildChain()` method:**
     ```java
     private static Consumer<NodeWithExplainOut> buildChain(
             List<ResolvedStep> steps, Consumer<NodeWithExplainOut> terminal, ICoreSession session)
     ```
     Iterates steps in REVERSE order, wrapping each step around the current downstream consumer via `wrapStep()`. Returns the chain head.

  3. **Add private `wrapStep()` dispatcher:**
     ```java
     private static Consumer<NodeWithExplainOut> wrapStep(
             ResolvedStep step, Consumer<NodeWithExplainOut> downstream, ICoreSession session)
     ```
     Uses `switch` on the sealed `ResolvedStep`:
     - `FilterStep` → `wrapFilter()`
     - `TraverseStep` → `wrapTraverse()`
     - `UnionStep` → `wrapUnion()`
     - `RepeatStep` → log info "out of scope", return `item -> {}` (swallow)
     - `UnsupportedStep` → log warning, return `item -> {}` (swallow)

  4. **`wrapFilter(FilterStep, Consumer<NodeWithExplainOut>, ICoreSession)`** returns:
     ```java
     item -> {
         if (ExpressionEvaluator.evaluate(f.predicate(), item.node(), session)) {
             downstream.accept(item);
         }
     }
     ```
     Pure push, no list.

  5. **`wrapTraverse(TraverseStep, Consumer<NodeWithExplainOut>, ICoreSession)`** returns a consumer that:
     - If edge is unknown → return `item -> {}` with LOG.warning
     - Otherwise, for each input item, iterate all `EdgeAlternative`s and push targets directly to downstream.
     - `MDependencyEdge` traversal: check `dep.getSource().isInstance(node)`, call `node.mGet(dep)`, for each valid target create extended path and push via `downstream.accept(new NodeWithExplainOut(target, extendedPath))`. Skip invalid elements with `LOG.debug()`.
     - `LinkObjectEdge` traversal: same logic as current `traverseLinkForward`/`traverseLinkBackward`, but push results directly to `downstream.accept()` instead of adding to a list. Keep edge filter evaluation, stereotype matching, validity checks.
     - Preserve all existing helper methods: `matchesStereotype()`, `isValidElement()`, `extendPathForLink()`, `extendPathForDep()`. These are pure functions and don't need changes.

  6. **`wrapUnion(UnionStep, Consumer<NodeWithExplainOut>, ICoreSession)`** returns a consumer that:
     - Pre-builds a `List<Consumer<NodeWithExplainOut>>` of branch head consumers (one per branch) by calling `buildChain(branch, downstream, session)` for each branch.
     - For each input item, feeds it to EACH branch head consumer sequentially:
       ```java
       item -> {
           for (Consumer<NodeWithExplainOut> branchHead : branchHeads) {
               branchHead.accept(item);
           }
       }
       ```
     - This means output is interleaved per-item (branch 1 results from item X, then branch 2 results from item X, then next item). This is acceptable because: (a) dedup at the terminal makes ordering irrelevant for the final result set, (b) no buffering needed, (c) branches are still processed sequentially per-item (not concurrently).
     - Keep LOG.debug for branch count. Remove per-branch item count logging (not available in streaming model without adding a counter, which is noise).

  7. **Replace `executeSteps()` with `executeToList()` (package-private, for EXISTS):**
     ```java
     static List<NodeWithExplainOut> executeToList(
             List<ResolvedStep> steps, List<NodeWithExplainOut> input, ICoreSession session)
     ```
     Implementation: create `List<NodeWithExplainOut> results = new ArrayList<>()`, call `buildChain(steps, results::add, session)` to get chain head, feed each input item through the chain head, return results. This is the ONLY place intermediate list collection happens, and it's used exclusively for EXISTS sub-queries where input is a single element (small scope).

  8. **Remove all old list-returning methods**: `execute()`, `executeSteps()`, `executeStep()`, `executeFilter()`, `executeTraverse()`, `executeUnion()`, `traverseMDependency()` (the list-based version), `traverseLinkObject()`, `traverseLinkForward()`, `traverseLinkBackward()`. The traverse helper logic is inlined into the consumer returned by `wrapTraverse()`. Pure helper methods (`matchesStereotype`, `isValidElement`, `extendPathForLink`, `extendPathForDep`) are preserved unchanged.

  **QueryEngine.runQuery() changes:**

  Replace the `sourceCollector` buffering pattern:
  ```java
  // BEFORE (buffering):
  SyncQueryResponse sourceCollector = new SyncQueryResponse();
  SourceEvaluator.evaluate(resolvedQuery.source(), this.session, sourceCollector);
  sourceCollector.diagnostics().forEach(responseFiller::pushDiagnostic);
  StepPipelineExecutor.execute(resolvedQuery.steps(), sourceCollector.items(), this.session, responseFiller);

  // AFTER (streaming):
  IQueryResponseFiller pipeline = StepPipelineExecutor.buildPipeline(
          resolvedQuery.steps(), this.session, responseFiller);
  SourceEvaluator.evaluate(resolvedQuery.source(), this.session, pipeline);
  ```
  The `if (steps.isEmpty())` branch stays unchanged (direct push to responseFiller). Remove the `SyncQueryResponse` import if no longer used by this file. Remove the `StepPipelineExecutor.execute` import — `buildPipeline` is the only entry point now.

  **ExpressionEvaluator.evaluateExists() changes:**

  Replace:
  ```java
  List<NodeWithExplainOut> subResults = StepPipelineExecutor.executeSteps(ex.in(), singletonInput, session);
  ```
  With:
  ```java
  List<NodeWithExplainOut> subResults = StepPipelineExecutor.executeToList(ex.in(), singletonInput, session);
  ```
  The rest of the method (WHERE clause filtering, `!isEmpty()` check) stays unchanged. This is a one-line rename.

  **What NOT to change:**
  - `SourceEvaluator` — already streams via IQueryResponseFiller, no changes needed.
  - `SyncQueryResponse` — unchanged, still the terminal accumulator.
  - `IQueryResponseFiller` interface — unchanged.
  - `KindMatcher`, `PropertyValueReader` — unchanged.
  - No public API changes (`IQueryEngine`, `IASyncExecution`, `syncExec`, `prepareAsync`).

  **Code style reminders:**
  - Use explicit types, not `var`.
  - Use `this.` for instance field access.
  - Add Javadoc on all public/package-private methods.
  - Keep `@objid` annotations on any code that already has them (but do NOT add new ones).
  - Use `java.util.function.Consumer` for the push chain — no custom functional interface needed.
  - Use Java 21 switch expressions with sealed types where already used.
