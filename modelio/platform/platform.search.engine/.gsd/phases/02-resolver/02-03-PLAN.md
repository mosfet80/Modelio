<task type="auto">
  <name>Task 2: Add PropertyKeyRegistry that indexes attributes, tags, notes, and property definitions</name>
  <files>
    platform.search.engine/src/org/modelio/platform/query/engine/resolver/PropertyKeyRegistry.java,
    platform.search.engine/src/org/modelio/platform/query/engine/resolver/ResolverContext.java
  </files>
  <action>
    Implement a `PropertyKeyRegistry` that can answer: "what definitions might this key refer to?".

    Indexing scope (v1):
    - Attributes: across metaclasses in the metamodel (MAttribute name matches).
    - TagTypes / NoteTypes: discoverable via profiles + stereotypes (reuse `MModelServices` traversal patterns from Phase-2 research).
    - Typed property definitions: discoverable via `PropertyTableDefinition` on:
      - `Stereotype.getDefinedTable()`
      - `MetaclassReference.getDefinedTable()`

    Design constraints:
    - Matching is exact string match after trim; case-sensitive.
    - Dots are legal and treated as normal characters.
    - Registry can be built lazily (on first request) and cached.
    - Ensure the registry API can be unit-tested with stubs (avoid requiring a real model session in tests).

    If needed, extend `ResolverContext` with minimal enumeration methods for modules/profiles/references/stereotypes.
  </action>
  <verify>
    Host bundle builds (`platform.search.engine/build` aggregator).
  </verify>
  <done>
    PropertyKeyRegistry exists and can provide candidate definitions per key without rescanning on every lookup.
  </done>
</task>

  <name>Task 3: Implement PropertyKeyResolver and diagnostics</name>
  <files>
    platform.search.engine/src/org/modelio/platform/query/engine/resolver/PropertyKeyResolver.java
  </files>
  <action>
    Implement `PropertyKeyResolver` resolving a raw key token into `ResolvedPropertyKeyRef`:

    - Normalize: trim only; case-sensitive.
    - Lookup in PropertyKeyRegistry and build alternatives:
      - AttributeKey(MAttribute)
      - TagKey(TagType)
      - NoteKey(NoteType)
      - PropertyDefinitionKey(owner + PropertyDefinition)

    Diagnostics:
    - 0 alternatives → WARNING "unknown property key".
    - >1 alternatives → WARNING "ambiguous property key" listing categories + key names.

    Determinism:
    - Stable ordering by category (Attribute, Tag, Note, PropertyDefinition) then by qualified identifier.
  </action>
  <verify>
    Unit tests cover unknown + ambiguous + owner preservation.
  </verify>
  <done>
    PropertyKeyResolver produces alternatives per key and emits correct diagnostics.
  </done>
</task>
