    - Build maps token → candidates on first use (lazy) and cache in the registry instance.

<task type="auto">
  <name>Task 2: Implement EdgeResolver and diagnostics</name>
  <files>
    platform.search.engine/src/org/modelio/platform/query/engine/resolver/EdgeResolver.java
  </files>
  <action>
    Implement `EdgeResolver` resolving `(edgeToken, direction)` into `ResolvedEdgeRef`:

    - Normalize token: `trim()` only; case-sensitive.
    - Lookup candidates from EdgeRegistry:
      - Dependency alternatives: `ResolvedEdgeRef.DependencyEdge(MDependency, direction)`
      - Link-object alternatives: `ResolvedEdgeRef.LinkObjectEdge(MClass linkMetaclass, Stereotype stereotypeOrNull, direction)`

    Diagnostics behavior:
    - 0 alternatives → diagnostic (WARNING) "unknown edge".
    - >1 alternatives → diagnostic (WARNING) "ambiguous edge" listing retained alternatives.

    Determinism:
    - Keep stable ordering (dependency edges first, then link edges). Within categories, sort by qualified name where available.

    Input kind usage:
    - Accept an optional `ResolvedKindRef inputKind` (or equivalent) and use it to filter edge candidates when possible.
    - If `inputKind` is ambiguous, keep compatible alternatives per candidate kind; do not collapse ambiguity.
  </action>
  <verify>
    Unit tests added in next task cover unknown + ambiguous + direction propagation.
  </verify>
  <done>
    EdgeResolver resolves tokens to ResolvedEdgeRef alternatives and emits correct diagnostics.
  </done>
</task>
