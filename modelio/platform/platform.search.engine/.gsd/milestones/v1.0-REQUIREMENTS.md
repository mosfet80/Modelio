# Requirements: Modelio MQL Resolution & Execution Engine (v1)

**Defined:** 2026-02-06
**Core Value:** Execute MQL queries with bounded, deterministic traversal and explainable results.

## v1 Requirements

### Resolved Model

- [x] **RSM-01**: An internal resolved query model exists and is sufficient to execute MQL v1 semantics without depending on unresolved names.
- [x] **RSM-02**: Resolved model can represent ambiguous user references as explicit unions (alternatives) without losing information.

### Name Resolution

- [x] **RES-01**: Resolve `KindRef` case-sensitively, accepting both simple and qualified metaclass names.
- [x] **RES-02**: If a `KindRef` matches multiple definitions (metaclass and/or stereotype), resolver produces a union of alternatives and emits a diagnostic listing retained alternatives.
- [x] **RES-03**: Resolve `EdgeRef` case-sensitively to the union of valid interpretations (structural `MDependency`, link metaclass, stereotype applying to link metaclass) and emit ambiguity diagnostics when applicable.
- [x] **RES-04**: Resolve element property keys case-sensitively to the union of matching definitions (`MAttribute`, `TagType`, `NoteType`, `PropertyDefinition`) and emit ambiguity diagnostics when applicable.
- [x] **RES-05**: Unknown/invalid references (kind/edge/property) produce a diagnostic and do not crash execution.

### Execution Engine

- [x] **EXE-01**: Execution runs from `Source` (all/provided) and applies pipeline steps (filter/traverse/union/repeat) according to the MQL technical specification.
- [x] **EXE-02**: Execution returns an `IQueryResponse` where `items()` delivers results and results are produced incrementally (streamed).
- [x] **EXE-03**: Each result item includes an explanation path (`why`) sufficient to understand how the node was reached.
- [x] **EXE-04**: Execution produces a diagnostics stream (`diagnostics()`) including: ambiguity warnings, cycle/graph warnings (when relevant), errors, and informational messages (limits reached).
- [x] **EXE-05**: Execution is bounded by `LimitsSpec` (`timeoutMs`, `maxDepth`, `limit`) and sets `isTruncated()` when a limit stops the run.
- [x] **EXE-06**: Union semantics deduplicate results with deterministic behavior (no uncontrolled duplicates) while keeping performance acceptable on large models.

### Acceptance & Tests

- [x] **ACC-01**: Implement enough semantics to execute the acceptance queries Q1–Q15 defined in the split technical specification.
- [x] **ACC-02**: Add automated tests in `platform.search.engine.test` covering resolution and execution behavior for Q1–Q15 (or equivalent fixtures).

## v2 Requirements

- **V2-01**: Introduce a textual grammar + parser for MQL v1.
- **V2-02**: Add support for vNext features (e.g., aggregations) once specified.

## Out of Scope

| Feature | Reason |
| --- | --- |
| Textual grammar + parser | Spec explicitly scopes v1 to AST-driven execution |
| Reactive streaming libraries | Use in-house `AsyncIterator` API |
| Editing `core.query/.../model/runtime` backup prototype | Read-only inspiration; avoid divergence |
