# Milestone v1.0: Modelio MQL Resolution & Execution Engine

**Status:** ✅ SHIPPED 2026-02-26
**Phases:** 1–8 (+ 7 inserted decimal phases)
**Total Plans:** 34

## Overview

This milestone turned the existing MQL public DTO model (unresolved AST + frozen wire model + result DTOs) into a runnable MQL v1 engine by adding: (1) an internal resolved query model, (2) a resolver that expands ambiguous names into explicit alternatives, and (3) a bounded, streaming executor producing explainable results. The milestone also included per-step diagnostic attribution, real-time validation feedback in the MQL graphical editor (Phase 8), and a comprehensive acceptance test suite (Q1–Q15).

## Milestone Summary

**Decimal Phases (Inserted):**

- Phase 2.1: QueryResolver coverage – dynamic subtype discovery guardrails (inserted after Phase 2)
- Phase 3.01: AsyncIterator API simplification – hard-break migration to `nextAsync(Optional)` (inserted after Phase 3)
- Phase 3.02: Logging migration – replace System.Logger with SearchEngine.LOG (inserted after Phase 3.01)
- Phase 3.03: Response API refactor – `syncExec`/`prepareAsync` split (inserted after Phase 3.02)
- Phase 3.04: Manual API rework – QueryCompletionStatus, SyncQueryResponse, IQueryResponseFiller (inserted after Phase 3.03)
- Phase 4.1: Streaming fix – push-based Consumer pipeline, no intermediate buffering (inserted after Phase 4)
- Phase 5.1: StepPipelineExecutor decomposition – TraverseStepExecutor + RepeatStepExecutor extracted (inserted after Phase 5)

**Key Decisions:**

- Unknown Step/Expr subtypes throw UnsupportedOperationException (avoid silent resolver gaps)
- Use instanceof dispatch for expr resolution (Java 17 compatibility)
- Single async pull contract `nextAsync()` for AsyncIterator (reduce API ambiguity)
- `IQueryEngine` exposes `syncExec(Query)` and `prepareAsync(Query)`, no longer `execute(Query)`
- Push-based Consumer<NodeWithExplainOut> chain eliminates intermediate List buffering between steps
- Cycle detection via path check not globalVisited — distinguishes proper cycles from convergence
- EXECUTION_TRUNCATED replaces LIMIT_REACHED/TIMEOUT_REACHED as primary truncation code
- Budget counts post-dedup unique items (limit reflects distinct result items at terminal consumer)
- All log statements migrated to centralized `SearchEngine.LOG` (PluginLogger)
- 19 MQL i18n keys externalized to `SearchEngine.properties` via `SearchEngineI18N.msg()`
- Per-step StepResolutionResult enables GEF figure diagnostic decoration with severity icons
- Execute button gated on ERROR diagnostics in MqlEditorDialog

**Issues Resolved:**

- ProvidedSource pattern: elements supplied via engine supplier, not constructor (EdgeResolver bugfix)
- EdgeResolver anyKind() root metaclass (SmObject) caused empty traverse results — right fix: treat superclasses of expected class as compatible
- Accentuated French properties verified loading correctly in SearchEngine.I18N

**Issues Deferred (Tech Debt):**

- Q2 (stereotype filter): @Disabled — stereotype registry unavailable in MofMetamodel test sessions
- Q13 (cursor pagination): @Disabled — cursor pagination not yet implemented in v1
- PreparedAsyncExecution.run() executes synchronously on calling thread — SWT Job wrapper needed
- SearchEngine.I18N null risk if bundle starts before BundleActivator.start() completes
- UI → Query execution not wired: OpenMqlEditorHandler discards dialog return value — Phase 9 scope

**Technical Debt Incurred:**

- MqlEditorDialog creates QueryEngine twice (validation + execution will need separate instances) — Phase 9 fix
- No explicit multi-Repeat-step integration test proving globalVisited prevents cross-step revisit
